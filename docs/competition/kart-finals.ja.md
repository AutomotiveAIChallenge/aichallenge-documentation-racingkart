## 実車で走らせるときの注意点 { #real-vehicle-notes }

運営側の実車実験で分かったことのうち、参加チームの実装に影響するものをまとめます。

### V2X の通信遅延 { #v2x-delay }

実車では車両と MQTT broker の間を経由して位置情報を共有するため、シミュレータ内の即時共有とは異なり遅延と欠損が発生します。実測では遅延は平均 90 ms 程度、配信頻度は 20 Hz でした。AWSIM 側にも同等の伝送遅延（車両ごとに 100〜200 ms）が入っています。

遅延への対処はアルゴリズム側の責務です。受信位置の外挿、古いデータの破棄、遅延を前提とした余裕距離の確保を行ってください。遅延未対応のままだと、追突判定や追い越し判断が破綻します。

### 駆動力と速度 { #traction }

- 上り坂や一部カーブで加速トルクが不足し、一度停止するとスロットル 100% でも再発進が困難でした。カーブで止まらない走行ラインと速度計画が重要です。
- 「一気に加速してブレーキ」というポンピング的な挙動が観測されました。accel/brake map の未整備や MPC の縦方向制御が原因の可能性があります。アクセル上限、速度設定の見直しが有効な場合があります。
- 速度指令はそのまま実速度になりません。VCU 側で 26 km/h 程度に制限されます。加速の出方はシミュレータと異なるため、シミュレータでの最速ラインが実車で再現できるとは限りません。
- 昨年度の上限速度は30km/h程度に制限されていました。

### 自己位置と通信 { #localization }

- RTK 補正（NTRIP）がたまにFix しない場合でも、自己位置推定ができる状態にしておいてください。
- IMU のジャイロバイアスは車両ごとに実測して反映する必要があります。手順は[実車両の起動](../vehicle/run.ja.md)の「1-2. IMU バイアスの修正」を参照してください。

### スタート時の挙動 { #start-behavior }

レース開始を表すトピックは配信されず、手動操作モードから自動モードに切り替わるだけになる予定です。**スタート位置での待機中にスタック判定が働き、いきなり後退や切り返しを始めないよう、各チームで対処してください**。

### rosbag { #rosbag }

走行中の rosbag には V2X の車両位置（`/v2x/vehicle_positions`）も記録されます。**rosbag を各チームが持ち帰ることはできません**。運営が SharePoint で共有しますので、振り返りにはそちらを参照してください。V2X の受信周期、RTK Fix が外れた区間での自己位置の飛び、制御指令と実加速度のずれを確認することを推奨します。

## 後日掲載する情報 { #tbd }

- 当日の進行、タイムテーブル、役割分担
- V2X 証明書（`kart.crt`）の配布時期と、車両 ID の割り当て
