# 実機決勝での参加者操作

Sim to Real SW 部門の実機決勝（9月20日・シティサーキット東京ベイ）で、参加チームが実車両をどう操作するかをまとめたページです。競技ルール・順位決定方式は[Sim to Real部門ルール](../competition/sw-class.ja.md#final-abst)を参照してください。

実機決勝では、**事前に提出したコードがそのまま車両上で動きます**。当日にできるのはパラメータのチューニングと遠隔手動操作だけです。この前提から、事前準備として dynamic reconfigure 対応とチューニング用 TUI の実装が必須になります。

!!! warning "当日は再ビルドできません"
    走行枠のあいだ、車両 PC 上でのコード変更・再ビルドは一切できません。走行を見ながら調整したい値は、**すべて実行中に変更できる形（dynamic reconfigure）で実装しておく**必要があります。ビルドが必要な変更は当日反映できません。

## 第1部 事前準備

### 1-1. コードの提出

実機決勝で使用するコードを、指定期日までに運営へ提出します。

| 項目 | 内容 |
| --- | --- |
| 提出期限 | 9月◯日（詳細は後日アナウンス） |
| 提出物 | 実機決勝で走らせるコード一式 |
| 提出後 | 運営が車両上でビルド・起動して動作を確認します |

提出後、運営側で動作確認を行います。ここでビルドが通らない・起動しないといった問題が見つかった場合は個別に連絡します。**期限後のコード差し替えはできません**ので、提出前に手元で `make autoware-build` が通ること、起動して走行できることを必ず確認してください。

### 1-2. dynamic reconfigure への対応

当日チューニングしたいパラメータは、ノードを再起動せずに変更できるようにしておきます。ROS 2 のパラメータを宣言し、`rclcpp::Node::add_on_set_parameters_callback`（C++）または `Node.add_on_set_parameters_callback`（Python）で変更を受け取る実装にしてください。

対応していないパラメータは、当日 launch ファイルや YAML を書き換えても反映できません（再起動・再ビルドができないため）。

チューニング対象になりそうな値の例は次のとおりです。

- 制御ゲイン（`lookahead_gain`、`lookahead_min_distance` など）
- 目標速度・加減速度の上限
- 障害物回避や追い越しの判断しきい値

どのパラメータを可変にするかは、[開発のアイデア](../development/development-ideas.ja.md)で挙動への影響を確認しながら、走行中に触りたくなる値を洗い出して決めてください。

### 1-3. チューニング用 TUI の実装（必須）

当日のチューニングは、参加チームが用意した TUI（ターミナル UI）から行います。**TUI の用意は必須です**。

| 項目 | 要件 |
| --- | --- |
| 起動コマンド | `make tui` で起動できること |
| 機能 | 1-2 で dynamic reconfigure 対応したパラメータを、走行中に確認・変更できること |
| 動作環境 | 車両 PC（ECU）上で動作すること。オペレーションブースの PC から SSH 経由で操作します |

`make tui` という起動方法は運営側で統一します。当日、参加チームがオペレーションブースに着いた時点でこの TUI が既に起動・表示された状態になっているため、起動コマンドが違うと当日の進行に間に合いません。

SSH 接続が切れても `make tui` を実行し直せば操作を再開できるようにしておくと、当日のトラブル時に復帰しやすくなります。

!!! tip "車両 PC 操作 TUI（`make vehicle-tui`）とは別物です"
    リポジトリには運営が走行枠の準備に使う `make vehicle-tui` がありますが、これはビルドや起動といったセットアップ手順を進めるためのものです。参加チームが用意するチューニング用 TUI（`make tui`）とは役割が異なります。

## 第2部 当日の操作

### 2-1. オペレーションブース到着時の状態

参加チームがオペレーションブースに着いた時点で、運営側の準備は以下まで完了しています。

1. 提出されたコードが車両 PC 上でビルド済み
2. Autoware・driver・zenoh・rosbag が起動済み
3. ブースの PC から車両 PC へ SSH 接続済みで、その端末で `make tui` によりチューニング用 TUI が起動・表示された状態

参加チームはこの状態から、TUI での操作を引き継ぎます。車両 PC 上の操作はすべてこの SSH 接続経由で行います。

### 2-2. TUI でのチューニング

表示されている TUI からパラメータを変更します。変更は走行中でも反映されます。

走行の様子は RViz でも確認できます。RViz の起動・遠隔 PC 側の構成は[遠隔操作](remote.ja.md)を参照してください。

!!! warning "操作前に運営へ申告してください"
    パラメータ変更を含め、車両への操作を行う前には運営に申告する必要があります。また、自チームの `ROS_DOMAIN_ID` 以外に影響を及ぼす操作は禁止です（[Sim to Real部門ルール](../competition/sw-class.ja.md#final-rule)）。

### 2-3. ゲームコントローラによる遠隔手動操作

参加チームにはゲームコントローラ（ロジクール F310）が渡されます。これで車両を遠隔から手動操作できます。

- **自動運転と手動操作は任意のタイミングで切り替えられます。** 走行中いつでも手動に切り替えて車両を動かし、また自動に戻すことができます。
- スタックした場合や、車両が予期せぬ挙動をした場合の復帰は参加チーム自身で行います。運営によるサポート（遠隔操作・物理的介入）はありません。
- ただし、**手動運転を多用することは禁止**です。また、運営が危険と判断した場合は運営側で緊急停止・車両移動を行うことがあります。

ボタンと軸の割り当ては[遠隔操作 - ゲームコントローラの使い方](remote.ja.md)を参照してください。

## 第3部 当日にできること・できないこと

| 操作 | 可否 |
| --- | --- |
| TUI からのパラメータ変更 | ○（運営への申告が必要） |
| ゲームコントローラによる遠隔手動操作 | ○（多用は禁止） |
| 自動・手動の切り替え | ○ |
| 自己位置の再設定 | ○（運営への申告が必要） |
| `ros2 topic` によるギア切り替え・ターボコマンド発行 | ○（運営への申告が必要） |
| コードの変更・再ビルド | × |
| launch ファイル・YAML の書き換えによるパラメータ変更 | ×（再起動できないため反映されません） |
| 提出物の差し替え | × |
| 自チームの `ROS_DOMAIN_ID` 以外に影響する操作 | × |

以下の場合は走行を中止します。

- コースの壁が大きく動いてしまった場合
- コースから大きく逸脱した場合
- その他、安全上の問題等でスタッフが指示した場合
