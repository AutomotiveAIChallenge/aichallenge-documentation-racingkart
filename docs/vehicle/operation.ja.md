# 実機決勝での参加者操作

!!! warning "WIP"

    このページは作成中です。確定した情報は順次更新します。

Sim to Real SW 部門の実機決勝（9月20日・シティサーキット東京ベイ）で、参加チームが実車両をどう操作するかをまとめたページです。競技ルール・順位決定方式は[Sim to Real部門ルール](../competition/sw-class.ja.md#final-abst)、当日のスケジュールと走行枠中にできる操作は[実機決勝特設ページ](../competition/kart-finals.ja.md)を参照してください。

!!! warning "事前に提出したコードがそのまま車両上で動きます"
    走行枠のあいだ、車両 PC 上でのコード変更・再ビルドは一切できません。当日できるのはパラメータのチューニングと遠隔手動操作だけです。走行を見ながら調整したい値は、**すべて実行中に変更できる形（dynamic reconfigure）で実装しておく**必要があります。

## 第1部 当日の画面と操作

### 1-1. オペレーションブースで引き継ぐ状態

運営がブースの PC で `make workspace` を実行し、4 分割された Terminator（ターミナルアプリ）を表示した状態でお渡しします。参加チームが環境構築や `make workspace` の実行を行う必要はありません。

引き継ぎ時には、提出されたコードのビルド、Autoware・driver・zenoh の起動、車両 PC への SSH 接続まで運営が済ませています。rosbag の記録も運営が管理します（参加チームへの提供はありません）。

最初に、左上の車両操作 TUI のヘッダに表示された車両番号（例：`[A2]`）が、運営から案内された対象車両と一致することを確認してください。違う番号が表示されている場合は、操作を始めず運営に伝えてください。

### 1-2. 4 つのペインの見方

操作したいペインをマウスでクリックしてから、キー入力を行います。

＜ここに参加者へ渡す状態の Terminator 全体の画像を入れる。左上に①「車両操作 TUI」、左下に②「監視・チューニング」、右上に③「運営用 TUI」、右下に④「GUI ツール起動用端末」と注釈を付ける＞

| 番号・位置 | ペイン | 用途と操作する人 |
| --- | --- | --- |
| ① 左上 | `tui`（車両 TUI） | 参加者が Autoware の状態を確認し、必要な場合に停止・起動します |
| ② 左下 | `monitor`（監視） | 車両 PC 上の Autoware コンテナ内の端末です。参加者が ROS 2 コマンドで状態を確認し、パラメータを操作します |
| ③ 右上 | `staff`（運営 TUI） | 運営が driver・zenoh・rosbag を管理します。参加者はこのペインを操作しません |
| ④ 右下 | `gui`（GUI tools） | 手元のブース PC で GUI ツールを起動する端末です。RViz やゲームコントローラの通信に使います |

GUI ツールは④の端末内ではなく、**別ウィンドウ**として開きます。RViz も別ウィンドウで表示されます。

＜ここに GUI ツールの画像を入れる。Vehicle ID、RViz の操作ボタン、Joy の操作ボタンに注釈を付け、Terminator とは別ウィンドウであることが分かるようにする＞

GUI ツールの `Vehicle ID` も対象車両と一致していることを確認します。走行中に接続先を変更したり、Zenoh・Joy を停止したりしないでください。通信の停止は遠隔手動操作や車両の安全機能に影響するため、問題がある場合は運営へ伝えてください。

!!! note "2 種類の TUI があります"

    ①の **車両操作 TUI**（`make vehicle-tui`）は、Autoware の状態確認・停止・起動に使います。パラメータの調整には、チームが提出物に含める **チューニング用 TUI**（`make tui`）を使います。

### 1-3. 走行枠中に行うこと

1. 車両操作 TUI と GUI ツールの車両番号を確認します。
2. RViz で自己位置や車両の状態を確認します。RViz が表示されていない場合は、GUI ツールの `Start RViz` を使います。
3. 必要なパラメータをチューニング用 TUI から変更します。
4. ゲームコントローラで、自動運転と遠隔手動操作を切り替えて走行します。
5. Autoware の再起動が必要になった場合は、1-5「車両操作 TUI の見方と Autoware の再起動」の手順に従います。

!!! warning "操作前に運営へ申告してください"

    パラメータ変更を含め、車両への操作を行う前には運営に申告する必要があります（自己位置の再設定と `ros2 topic` によるギア切り替え・ターボコマンド発行は申告不要）。また、自チームの `ROS_DOMAIN_ID` 以外に影響を及ぼす操作は禁止です（[Sim to Real部門ルール](../competition/sw-class.ja.md#final-rule)）。

### 1-4. チューニング用 TUI でのパラメータ調整

運営が、チームの用意したチューニング用 TUI を起動してお渡しします。各項目の操作方法は、チーム自身が実装した TUI の仕様に従ってください。dynamic reconfigure に対応したパラメータは、走行中でも変更が反映されます。

!!! note "表示先は調整中"

    チューニング用 TUI の表示先と、監視端末への切り替え方法は確定後に追記します。

＜ここにチームのチューニング用 TUI の表示例を入れる。Terminator のどのペイン、または別端末に表示されるかが分かる画像にする＞

チューニングに使える時間は試合の進行によって異なります。準決勝には自由走行（10〜25分）があり、ここが主なチューニング時間です。決勝は待機時間が短く、パラメータをじっくり詰める余裕はありません（[試合スケジュール](../competition/kart-finals.ja.md#match-schedule)）。

②の監視端末では、例えば次のコマンドで状態を確認できます。すでに Autoware コンテナ内の端末を開いた状態でお渡しするため、手元の PC から改めてコンテナに入る操作は不要です。

```bash
ros2 node list
ros2 topic list
ros2 param list
```

### 1-5. 車両操作 TUI の見方と Autoware の再起動

①の車両操作 TUI では、上部の `running:` に稼働中のサービス、`stopped:` に停止中のサービスが表示されます。`autoware` の状態をここで確認できます。

＜ここに参加者用の車両操作 TUI の画像を入れる。車両番号、running / stopped、4 autoware-vehicle、6 autoware-vehicle down、failures、log に注釈を付ける＞

| キー | 操作 |
| --- | --- |
| ↑ / ↓ | 実行する項目を選択します |
| Enter | 選択した項目を実行します |
| `q` | 車両操作 TUI を終了します。Autoware を停止する操作ではありません |

項目の状態は `OK`（完了）、`NG`（失敗）、`>>`（実行中）、`-`（未完了）、`?`（前提の項目が未完了）で表示されます。`?` でも実行できるため、表示だけを見て次の項目へ進まず、当日の操作範囲に従ってください。チェックの結果は TUI のセッション内の記録なので、新しく TUI を開いた場合に未完了でも、提出物の展開やビルドをやり直す必要があるとは限りません。

| 番号・項目 | 用途 | 当日の扱い |
| --- | --- | --- |
| 1 `check preflight` | 起動前の環境確認 | 新しく TUI を起動した際にも自動実行されます。`NG` が出ている場合は運営に伝えます |
| 2 `extract` | 提出物の展開 | 運営が事前に済ませます。走行枠中に実行しません |
| 3 `build` | 提出物のビルド | 運営が事前に済ませます。走行枠中に実行しません |
| 4 `autoware-vehicle` | Autoware の起動 | 再起動時に使います |
| 5 `check runtime` | 起動後の環境確認 | 実行が必要な場合は運営に確認します。IMU バイアス計測の確認が出るため、走行中に計測しません |
| 6 `autoware-vehicle down` | Autoware の停止 | 再起動時に使います。driver・zenoh・rosbag は停止しません |
| 7 `cleanup` | 提出物とビルド成果物の片付け | コードとビルド成果物を消すため、参加者は実行しません |

Autoware を再起動する場合は、次の順で操作します。

1. 運営に再起動することを申告し、車両を安全に停止させます。
2. ①をクリックし、↑ / ↓ で `6 autoware-vehicle down` を選んで Enter を押します。
3. 停止処理が終了し、`stopped:` に `autoware` が表示されることを確認します。
4. `4 autoware-vehicle` を選んで Enter を押します。
5. `running:` に `autoware` が表示されることを確認し、RViz で自己位置や車両の状態を確認してから走行を再開します。

`running:` はコンテナの稼働状態を示します。これだけで自己位置や制御が正常であるとは判断せず、RViz などでも確認してください。再起動するとチューニング用 TUI や変更したパラメータに影響する場合があるため、必要に応じて TUI の再表示と設定値の確認を行います。

失敗した項目は `NG` と表示され、チェックの失敗内容は `failures`、処理の出力は `log` に残ります。失敗した項目名と、表示されている内容を運営へ伝えてください。

### 1-6. ゲームコントローラによる遠隔手動操作

参加チームにはゲームコントローラ（ロジクール F310）が渡されます。これで車両を遠隔から手動操作できます。

＜ここに F310 のボタンと軸の割り当て画像を入れる。自動運転と手動操作の切り替え、走行・操舵に使う操作が分かるようにする＞

ボタンと軸の割り当ての詳細は[遠隔操作](remote.ja.md)も参照してください。

- **自動運転と手動操作は任意のタイミングで切り替えられます。**
- スタックした場合や、車両が予期せぬ挙動をした場合の復帰は参加チーム自身で行います。運営によるサポート（遠隔操作・物理的介入）はありません。
- ただし、**手動運転を多用することは禁止**です。また、運営が危険と判断した場合は運営側で緊急停止・車両移動を行うことがあります。

### 1-7. 接続や画面に問題がある場合

| 状況 | 対処 |
| --- | --- |
| SSH が切れた、画面が更新されない | 車両の安全を確認し、運営へ伝えます。Terminator 全体を閉じたり、接続先を変更したりせず、再接続を依頼します |
| 車両操作 TUI を閉じてしまった | 運営へ再表示を依頼します。SSH 切断後も tmux セッションが残っていれば、同じ画面へ戻れます |
| RViz が閉じた | GUI ツールの `Start RViz` で開き直します。表示が戻らない場合は運営へ伝えます |
| 車両操作 TUI に `NG` が出た | 項目名と `failures` / `log` の内容を運営へ伝えます。提出物の展開・ビルド・cleanup で対処しようとしないでください |

### 1-8. 走行枠が終わったら

運営の指示に従って車両を停止し、操作を引き継ぎます。変更したパラメータや発生した問題があれば伝えてください。Terminator と GUI ツールは表示したままにし、参加者による `cleanup` や運営用 TUI での停止操作は行いません。

## 第2部 提出前の準備

### 2-1. コードの提出

実機決勝で使用するコードを、指定期日までに運営へ提出します。

| 項目 | 内容 |
| --- | --- |
| 提出期限 | 9/14 |
| 提出物 | 実機決勝で走らせるコード一式（SIM 予選と同じ `aichallenge_submit.tar.gz` 形式） |

提出後、運営が車両上でビルド・起動して動作を確認し、問題が見つかった場合は個別に連絡します。**期限後のコード差し替えはできません**ので、提出前に手元で `make autoware-build` が通ること、起動して走行できることを必ず確認してください。

### 2-2. dynamic reconfigure への対応

当日チューニングしたいパラメータは、ノードを再起動せずに変更できるようにしておきます。ROS 2 のパラメータを宣言し、`rclcpp::Node::add_on_set_parameters_callback`（C++）または `Node.add_on_set_parameters_callback`（Python）で変更を受け取る実装にしてください。制御ゲイン、目標速度・加減速度の上限、障害物回避や追い越しの判断しきい値などが対象になります。

対応していないパラメータは、当日 launch ファイルや YAML を書き換えても、Autoware を再起動しないと反映されません。再起動は可能ですが、限られた走行枠を消費するため推奨しません。

### 2-3. チューニング用 TUI の実装（推奨）

当日のチューニングは、参加チームが用意した TUI（ターミナル UI）から行います。

| 項目 | 要件 |
| --- | --- |
| 起動 | 運営が車両 PC 上で `make tui` を実行すると、autoware コンテナ内で提出物の `aichallenge_submit/tui.bash` が実行されます。このスクリプトを提出物に含めてください |
| 機能 | 2-2 で dynamic reconfigure 対応したパラメータを、走行中に確認・変更できること |
| 動作環境 | autoware コンテナ内（ROS 2 環境・`ROS_DOMAIN_ID` がスタックと揃った状態）で動作すること。オペレーションブースの PC から SSH 経由で操作するため、X 転送を前提にしないこと |

起動方法を運営側で統一するのは、参加チームがオペレーションブースに着いた時点で TUI を起動・表示済みにしておくためです。`make tui` は tmux 上で TUI を実行するため、SSH 接続が切れても TUI は残り、再接続後に同じ画面へ戻れます。

### 2-4. 安全ゲートのクリア（強く推奨）

[安全ゲート](../competition/sw-class.ja.md#safety-gate)（障害物停止・NPC 追い越し・車線維持）のクリアは必須ではありませんが、強く推奨します。実機決勝では反則回数が順位に直結し、衝突や停止はそのまま反則になるためです。実行方法は[安全ゲートシナリオの実行](../development/development-guide.ja.md#safety-gate)を参照してください。

### 2-5. 実車両特有の挙動への対処

V2X の通信遅延、ステアを切った状態での発進、スタート時の並び順など、シミュレータと実車両で異なる点があります。[実車両で走らせるときの注意点](../competition/kart-finals.ja.md#real-vehicle-notes)を確認し、必要な対処をコードに入れておいてください。特に、スタート待機中にスタック判定が働いて後退や切り返しを始めないようにする対処は、提出前に必ず入れてください。
